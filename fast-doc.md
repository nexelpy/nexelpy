
# NexelPy Documentation

## Introduction
NexelPy is a modern and fast framework focused on ease of development and intelligent resource management.

---

## Getting Started

### NexelPy Class
To create the main application, import the `NexelPy` class and create an instance of it.

**Important Note:** You must pass the path to the current file (`__file__`) as the `file` parameter. This parameter is crucial for internal path resolution and for the framework to understand the project structure.

```python
from nexelpy import Nexelpy

app = Nexelpy(__file__)

if __name__ == "__main__":
    app.run()
```

### Running the App
*   **In a Local Environment:** Use the following command in your terminal:
    `python main.py`
    You can also use the **Run Python File** button in VS Code or PyCharm.
*   **Technical Note:** The `run()` method is designed for development environments and offers features like `Auto-reload` and `Debug Mode`. For Production environments, use standard alternative methods.

### 🚀 Deployment (Production)
To run the project in production and server environments, it is recommended to use an ASGI Server like **Uvicorn** for maximum performance and stability:
```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

## Core Features

### 🔄 Reloader (Auto-Reload)
The reloader continuously watches Python files after the project starts. Saving any change in the Python code will automatically restart the project to apply the new changes immediately.

### 📂 Static Files Management
Managing static files in NexelPy is very simple and intelligent:
*   **Automatic Detection:** No need to manually define paths. Any folder named `static` at any level of the project will have its contents served directly.
*   **Wide Support:** Files with `.html`, `.css`, and `.js` extensions, even if outside the `static` folder, are automatically detected and made available as static files.

> **⚠️ Production Note:** For optimal performance, it is recommended to manage static files in the server environment using a Web Server like **Nginx**. If Nginx is not configured, a warning will be logged, indicating that file management is handled by the framework itself.

## Configuration & Parameters

### NexelPy Initialization
When creating an instance of the `NexelPy` class, you can configure the following parameters:

| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `file` | `str` | ✅ | Path to the main project file for Path Resolution. |
| `mountStatics` | `bool` | ❌ | If `True`, NexelPy will serve static files. |
| `secretKey` | `str` | ❌ | Security key for CSRF and Session encryption. The default value is generated by the framework. |
| `ignore_watch_dirs` | `str/list`| ❌ | List of directories that the reloader should not watch. |

#### Parameter `secretKey`
This key, generated by the `Fernet` algorithm, is available in all Views. 
**Warning:** In a Local environment, the value of this key changes every time the project restarts; therefore, any set Sessions will be invalidated upon restart. To prevent sessions from being invalidated on every restart, set the `NEXELPY_SECRET_KEY` environment variable in your `.env` file.

#### Parameter `ignore_watch_dirs`
If your project generates or uploads files that cause an infinite reload loop (e.g., the application generates Python files), enter the names of those directories in this parameter so the reloader ignores them.

```python
# Example as a single directory
ignore_watch_dirs = "my_folder"

# Example as a list
ignore_watch_dirs = ["folder1", "folder2"]
```

### Run Method Parameters
The `run` method is used for network configuration when running the application:

```python
app.run(host="127.0.0.1", port=8000)
```

### Routes and View

**Routing Management**

To register routes in the main module, use the `@app.route` decorator.

```python
from nexelpy import Nexelpy, View

app = Nexelpy(__file__)

@app.route("/")
async def home():
   x = View(__file__, title="Nexelpy")
   x.h2("Hello Nexelpy!")
   return x.RESPONSE()
```

#### Parameters of the `@app.route` Decorator
You can control the route's behavior using the following parameters:

`@app.route(route="/", methods=["GET", "POST"], prefix="/cpanel")`

* **`route`**: The main path (Endpoint).
* **`methods`**: List of allowed methods (NexelPy only supports `GET` and `POST` methods).
* **`prefix`**
The `prefix` parameter (Logical Segregation and Access Control)

Using `prefix` goes beyond a simple URL change. This parameter is used to create logical boundaries in large and scalable projects.

Application Segregation: In complex projects, you can define multiple different applications with separate prefixes (e.g., `/admin` for management and `/api` for services).
Access Control: Since all route specifications are available in `request.state.app`, the prefix allows you to easily apply security policies based on the path prefix. For example, you can restrict access to all sub-routes of a specific prefix.
Management in Graphical Panels: In administrative panels (like NexelPy's automatic panels), the prefix allows each application to be recognized as a separate entity, fully isolating its configurations, accesses, and user environment from other parts of the project.
    * *Example:* If `prefix="/cpanel"`, the final path will be `example.com/cpanel/`.

> **⚠️ Important Note: Mandatory `async` usage**
> The NexelPy framework is built on asynchronous operations. If you define a function without the `async` keyword, the program will stop with the following error:
> ```text
> (NexelPy Route Error)
>          handler: home
>          error: Handler must be async (use 'async def').
> ```

**View Class (Content Display)**

To build HTML responses and manage content, the `View` class is used. In NexelPy, using `__file__` is a standard pattern so that the view has access to the file structure.

```python
x = View(__file__, title="Nexelpy")
x.h2("Hello Nexelpy!")
return x.RESPONSE()
```

#### How it Works:
1.  **Create an Instance:** First, create an instance of `View`. The first input must always be `__file__`.
2.  **Build Content:** Add your content using the view methods (like `h2`, `p`, etc.). This instance is equipped with all the necessary tools for managing Requests, Responses, and headers.
3.  **Send Response:** Finally, by calling `x.RESPONSE()`, the final response object is sent to the client.

#### Parameters of the `View` Class
* **`file`**: The current file path for accessing resources.
* **`title`**: The page title (Title) which is placed in the `<title>` tag.

## Creating Views Independent of the Main Module

You can define Views in modules separate from the main project file. To define a Route in these modules, use the `@Route` decorator:

```python
# product.py
from nexelpy import View, Route

@Route("/product")
async def product():
    x = View(__file__, title="Product")
    return x.RESPONSE()
```

### Automatic Route Registration

There is no need to manually register Routes or directly import the module in `main.py`. When the application starts, NexelPy scans the project's Python modules. Directories excluded in the main application settings are not scanned.

Modules that use the `@Route` decorator are detected and loaded. Upon loading the module, the decorator executes and adds the corresponding Route to the main application. This mechanism is active in both local and server execution.

View function names do not need to be unique; NexelPy does not rely on the function name to register Routes.

The scanner does not scan the Main module.

## Basic View Structure

Creating an instance of `View` generates the initial structure of an HTML document including the `html`, `head`, and `body` tags:

```python
x = View(__file__, title="Product")
```

After creating the instance, you can create and add the required HTML elements to the document body.

## Creating HTML Elements

Through the `View` instance, you can create HTML elements using tag names. For example, `x.h1()` creates an `<h1>` element:

```python
x.h1(
    parent=None,
    text="Hello Nexelpy!",
    props="disabled",
    **attributes
)
```

Element creation parameters:

- `parent`: The parent element. The default is `None`, in which case the element is added to the `body`.
- `text`: The text inside the element.
- `props`: Valueless attributes, such as `disabled`.
- `**attributes`: HTML attributes passed as keyword arguments.

### Example

```python
x.button(
    "Click me",
    id="btn",
    Class="bg-red",
    data__number=43,
    props="disabled"
)
```

You can pass HTML attributes to the element as key-value pairs. For the `class` attribute, use `Class` with a capital C to avoid conflict with the reserved keyword `class` in Python.

To write a hyphen (`-`) in attribute names, use a double underscore (`__`). For example, `data__number` becomes the `data-number` attribute.

## Setting the Parent Element

Using the `parent` parameter, you can specify which element the new element will be created inside. The value of this parameter must be an element belonging to the same `View` instance. If `parent=None`, the element is added to the `body`.

```python
container = x.div(Class="container")
x.button("Click me", parent=container, id="btn", Class="bg-red")
```

In this example, the button is created inside the `div`. The resulting HTML structure looks like this:

```html
<div class="container"><button id="btn" class="bg-red">Click me</button></div>
```

## Creating Nested Elements with `with`

To create nested elements, you can use `with` blocks. In this method, child elements are created inside the parent element's block:

```python
with x.div(Class="container"):
    x.button("Click me", id="btn", Class="bg-red")

with x.section(Class="container"):
    with x.div():
        with x.button(id="btn", Class="bg-red"):
            x.span("Click me")
```

This approach shows the parent-child structure of elements with code indentation and reduces the need to create separate variables to hold each element.

## Adding Links to `head`

To add elements like CSS file links to the document `head`, specify the `x.headTag` value as the parent:

```python
x.link(parent=x.headTag, rel="stylesheet", href="/style.css")
```

## Base Tags Created During Initialization

When creating a `View` instance, the document's base tags are created and are accessible through the following properties:

```python
x.htmlTag
x.headTag
x.bodyTag
```

The `element` method is used to dynamically create HTML tags. By passing the tag name in the `tagName` parameter, you can create elements whose specific methods do not exist in the View.

The `parent` parameter specifies which parent element the created element should be placed inside. If `None` is passed, the element is created without a specified parent.

```python
 x.element(tagName="div", parent=None)
```

To create different tags, you can change the `tagName` value:

```python
x.element(tagName="article", parent=None)
x.element(tagName="custom-element", parent=None)
```

The `element` method allows the use of standard HTML tags and custom tags.

### Adding Raw HTML with `raw_html`

The `raw_html` method is used to directly add a piece of HTML to the View output. The HTML content is placed in the `html` parameter, and `parent` can be used to specify its location.

```python
@Route("/product")
async def product():
 x = View(__file__, title="product")
 x.raw_html(
 parent=None,
 html="""
 <div class="product">
 <h1>Product title</h1>
 <p>Product description</p>
 </div>
 """
 )
 return x.RESPONSE()
```

In this method, HTML is added to the View without the need to create each element separately using methods like `x.div()` or `x.p()`.

`raw_html` can be used to add ready-made HTML snippets or structures that are difficult or lengthy to create with the Element Builder. The content of this method must be handled with care, as the sent HTML is directly inserted into the output.

### Building Forms
To quickly build HTML forms, the `form`, `input`, and `submit` methods are available.

```python
with x.form(action="/submit", method="POST", Class="my-form"):
    x.input(type="text", name="username", placeholder="Enter name")
    x.input(type="password", name="password")
    x.submit("Send Data")
```

#### Redirecting Users
To redirect the user to another address, use the `x.redirect()` method. When this method is called, code execution stops and the redirect response is sent immediately (no `return` is needed).

```python
@Route("/admin")
async def admin():
    x = View(__file__)
    
    is_logged_in = await check_auth(x)
    if not is_logged_in:
        # Code execution stops and the user is redirected to the login page
        x.redirect("/login", status_code=307)
        
    x.h1("Welcome to Admin Panel")
    return x.RESPONSE()
```

## Plugins

Plugins are one of NexelPy's most powerful features, allowing you to split your Views into smaller, reusable parts. A plugin has access to all the capabilities of a View (such as head management, Redirect, Request access, and header settings).

### Creating a Simple Plugin

To create a plugin, use the `Plugin` class (passing `__file__` for path determination is mandatory). The `RESPONSE()` method in the plugin can return values as arguments to be used in the main View:

```python
from nexelpy import Plugin

async def my_plugin():
    x = Plugin(__file__)
    with x.section(Class="container"):
        with x.div():
            with x.button(id="btn", Class="bg-red"):
                x.span("click me")
    return x.RESPONSE("alex", 23)
```

### Creating Parametric Plugins

You can write plugin functions with arbitrary arguments to create custom elements:

```python
async def my_btn(text, id, Class):
    x = Plugin(__file__)
    with x.button(id=id, Class=Class):
        x.span(text)
    return x.RESPONSE()
```

### Using Plugins in a View

To use plugins in a View, use the `x.importPlugin` method. When calling the plugin in the import method, using the `await` keyword is mandatory.

```python
from nexelpy import View, Route
from plugins.btn import my_btn
from plugins.myplug import my_plugin

@Route("/product")
async def product():
    x = View(__file__, title="Product")
    
    # Use the button plugin
    x.importPlugin(await my_btn(text="click", id="btn3", Class="bg-green"))
    
    # Receive return values from the plugin (like Name and age)
    Name, age = x.importPlugin(await my_plugin())
    
    return x.RESPONSE()
```

How to receive return values:

The way `importPlugin` returns output depends on the number of values returned by the plugin:

If the plugin returns one value, `importPlugin` returns that value.
If the plugin returns more than one value, `importPlugin` returns them as a list, which you can receive using the Unpacking technique (like the example above).

### Advanced Features in Plugins

Plugins can inject their own CSS files into the page `head` or manipulate HTTP headers (like CSP). When the plugin is imported into the View, these changes are automatically applied to the page:

```python
from nexelpy import Plugin

async def my_btn(text, id, Class):
    x = Plugin(__file__)
    
    # Add the plugin's specific style file to the page header
    x.link(parent=x.headTag, rel="stylesheet", href="/plugin_style.css")
    
    with x.button(id=id, Class=Class):
        x.span(text)
        
    # Set Content Security Policy (CSP) in headers
    x.Headers.csp.add('default-src', "'self'")
    
    return x.RESPONSE()
```

### Redirect Management in Plugins

One of the key features of NexelPy plugins is the ability to perform conditional redirects. The `x.redirect()` method does not need to be `return`ed; as soon as it is executed, it stops the current execution flow (whether in the plugin or the view) and sends the redirect response directly to the client.

This feature allows the plugin to manage the application flow independently of the main view logic. For example, if data is not found, the plugin can redirect the user to the login page:

```python
from nexelpy import Plugin

async def get_data_plugin():
    x = Plugin(__file__)
    bands = await Band.select()
    
    if bands:
        for band in bands:
            x.p(f"name: {band['name']}")
    else:
        # If no data is found, a redirect is performed immediately and the rest of the code stops
        x.redirect("/login")
    
    # This line is only executed if a redirect has not occurred
    return x.RESPONSE()
```

**Technical Note:** When `x.redirect()` is called, the execution of the code block you are in (in the plugin or view) is stopped, and the redirect response is immediately sent to the browser. Therefore, you do not need to `return` the `x.RESPONSE()` value on the same line as the redirect.

## Widgets

For building simple and repetitive graphical elements that do not require header management, custom styles, redirects, or database access, using a **Widget** instead of a Plugin is recommended.

Widgets are actually simple, synchronous functions that receive the view or plugin object as input and build the desired HTML elements on it. Using this approach is much more performant than `importPlugin`, as it does not require the `await` process and heavy plugin lifecycle management.

### Creating a Simple Widget

A normal widget must receive the builder object (usually `x`) as input:

```python
# Define a widget as a simple, synchronous function
def my_button(obj, text, Class):
   obj.button(text=text, Class=Class)
```

### Using a Widget in a View

Here, we call the widgets easily and without the need for `await` inside the view:

```python
from nexelpy import View, Route

@Route("/product")
async def product():
   x = View(__file__, title="product")
   
   # Call widgets by passing the x object
   my_button(obj=x, text="add", Class="bg-green")
   my_button(obj=x, text="delete", Class="bg-red")
   my_button(obj=x, text="edit", Class="bg-yellow")
   
   return x.RESPONSE()
```

## Request Object Methods Guide

Here is a list of all methods, acceptable inputs, and how they work.

### 1. Data and Parameter Management
Many of the methods below (like `args`, `cookies`, `form`, `headers`, `json`, `path_params`, `payload`, `scope`, `state`) follow a single behavioral pattern:

*   **Without Argument:** If no key is passed, all available values are returned as a **list**.
*   **With Argument (Key):** If a specific key is passed, only the value corresponding to that key is returned.
*   **With Multiple Arguments (Multiple Keys):** If multiple keys are passed as `*args`, a list of values corresponding to those keys is returned (Unpacking capability).

| Method | Function | Example |
| :--- | :--- | :--- |
| `args()` | Get URL parameters | `name = await x.REQUEST.args("name")` <br> `names = await x.REQUEST.args("name", "age")` |
| `cookies()` | Get cookies | `val = await x.REQUEST.cookies("session_id")` |
| `form()` | Get form data | `val = await x.REQUEST.form("user_id")` |
| `headers()` | Get headers | `auth = await x.REQUEST.headers("Authorization")` |
| `json()` | Get JSON data | `user = await x.REQUEST.json("user")` |
| `path_params()` | Get path parameters | `id = await x.REQUEST.path_params("item_id")` |
| `scope()` | Get scope info | `val = await x.REQUEST.scope("key")` |
| `state()` | Get stored data | `val = await x.REQUEST.state("key")` |

### 2. Special Method `payload()`
This is the smartest method for accessing data, choosing the data source based on the HTTP request method:

*   **Inputs:** `method` (string like `"GET"`, `"POST"`, `"PATH"`, `"JSON"`) and `*keys`.
*   **Logic:**
    *   If `method="GET"`, it uses `args()`.
    *   If `method="POST"`, it uses `form()`.
    *   If `method="PATH"`, it uses `path_params()`.
    *   If `method="JSON"`, it uses `json()`.
*   **Output:** If the sent method does not match the request type, it returns `None`.

```python
# Practical payload example
name = await x.REQUEST.payload("GET", "name")
```

### 3. Other Methods and State Management

| Method | Output | Description |
| :--- | :--- | :--- |
| `app()` | `app` instance | Access the main application instance. |
| `body()` | `bytes` | Get the request body as bytes. |
| `client()` | `dict` | Get client details (browser, IP, etc.). |
| `method()` | `str` | Return the method type (e.g., `GET`). |
| `stream()` | `generator` | Get the request body as a stream. |
| `url()` | `url` object | Get full URL information. |
| `set_state()` | `None` | Store a value in `state` (e.g., `x.REQUEST.set_state(token="abc")`). |

## Header Management (HeaderBuilder)

These methods are available through `x.Headers` and are used to configure response security and behavior.

```py
from nexelpy import View, Route

@Route("/product")
async def product():
    x = View(__file__, title="product")
    
    # Add allowed sources to Content-Security-Policy
    x.Headers.csp.add('connect-src', "'self'", "https://api.example.com")
    
    # Set HSTS policy for forcing HTTPS (max age, subdomains, preload)
    x.Headers.hsts(max_age=31536000, include_subdomains=True, preload=True)
    
    # Set browser cache policies
    x.Headers.cache(cache_control="public, immutable", max_age=31536000)
    
    # Set Clickjacking prevention policy (values: DENY or SAMEORIGIN)
    x.Headers.frame_options(policy="SAMEORIGIN")
    
    # Enable MIME-sniffing prevention
    x.Headers.content_type_options()
    
    # Set Referrer-Policy
    x.Headers.referrer_Policy(policy="same-origin")
    
    # Control access to browser features like camera
    x.Headers.permissions_Policy.add('camera', 'https://meet.google.com')
    
    # Set COOP (Cross-Origin-Opener-Policy)
    x.Headers.cross_origin_opener(policy="same-origin-allow-popups")
    
    # Set COEP (Cross-Origin-Embedder-Policy)
    x.Headers.cross_origin_embedder(policy="unsafe-none")
    
    # Set CORP (Cross-Origin-Resource-Policy)
    x.Headers.cross_origin_resource(policy="cross-origin")
    
    # Origin-Agent-Cluster isolation
    x.Headers.origin_agent_cluster()
    
    # Clear site data on the client side (like cookies and storage)
    x.Headers.clear_site_data('cookies', 'storage')
    
    # Add custom and raw headers (underscores are converted to hyphens)
    x.Headers.add_raw_header(
        X_Custom_Header="custom-value",
        X_Another_Header="another-value",
        X_API_Version="v1.0"
    )
    
    # Default security header profiles
    x.Headers.set_super_strict()  # Highest security level
    x.Headers.set_strict()        # Strict security level
    x.Headers.set_normal()        # Standard and normal security level
    x.Headers.set_relaxed()       # Relaxed security level (development)

    return x.RESPONSE()
```

## Vapi Feature (Ajax-Driven Component Rendering)

One of **NexelPy**'s unique features is the **Vapi** system. This feature is designed to handle Ajax requests, moving the UI building process from the client to the server.

### Vapi Concept
In traditional methods, after receiving data from the server, the client must process the data and build HTML elements using JavaScript. But with **Vapi**, the entire process of building components (like product cards, lists, or dynamic sections) is done on the server, and the final, ready HTML snippet is sent to the client. The client's only task is to `append` this snippet.

**Practical Example:** In a product search system, with each keystroke, the word is sent to the server, relevant products are extracted from the database, built into server-designed cards, and finally, a ready HTML section is delivered to the client.

### Implementation Example

```python
from nexelpy import Vapi, Route

@Route("/send-card-api", methods=["POST"])
async def send():
    # Use Vapi instead of View for Ajax requests
    x = Vapi(__file__)
    
    # Get input value from the request body
    search_term = await x.REQUEST.payload("POST", "search")
    
    # Get relevant products from the database (assuming Piccolo ORM)
    products = await Product.select().where(Product.name == search_term)
    
    # Build the HTML structure on the server
    for product in products:
        with x.div(Class="product-card"):
            x.img(src=product.urlPic)
            x.h4(f"Product Name: {product.name}")
            x.p(f"Price: {product.price}")
            
    # Send the final response including the built HTML snippet
    return x.RESPONSE(status_code=200)
```

### Main Benefits
*   **Reduced Client Processing Load:** The client is not involved in heavy DOM calculations and building.
*   **Faster Development:** All UI design logic is centralized in one place (server-side).
*   **Higher Security:** Business logic and exact data structures remain hidden on the server side.
*   **Consistency:** Use the same syntax (`x.div`, `x.img`, etc.) to build dynamic parts.

---

### Vapi Response Structure

The `x.RESPONSE` method in the `Vapi` class, unlike a normal `View`, returns a `JSONResponse` object. This response includes a JSON dictionary containing the following keys:

| Key | Source | Description |
| :--- | :--- | :--- |
| `view` | `bodyTag content` | The HTML snippet generated on the server that should be `append`ed on the client. |
| `QE_links_header` | `headTag content` | Includes CSS links, scripts, and metadata injected into `<head>`. |
| `status_message` | `status_message` argument | The status message passed from the method. |
| `**data` (Custom Keys) | Additional arguments (`**kwargs`) | Any key and value the user sends in `RESPONSE` is added directly to this section. |

#### Custom Data Example
Users can send side data needed for client logic using `keyword arguments` (like `theme="dark"`):

```python
# Example: Sending HTML along with client theme settings
return x.RESPONSE(status_code=200, theme="dark", user_role="admin")
```

**The final JSON output on the client will look like this:**
```json
{
  "view": "<div class='product-card'>...</div>",
  "QE_links_header": "<link rel='stylesheet' href='...'>",
  "status_message": "",
  "theme": "dark",
  "user_role": "admin",
}
```

## API Responses Management (RestApi)

The `RestApi` class is designed to manage standard HTTP protocol responses. This class covers all common data sending scenarios.

### Response Methods List and Their Structure

Below is the exact signature of each method and its input parameters:

#### 1. `RESPONSE_json`
Send structured data in JSON format.
*   **Signature:** `x.RESPONSE_json(background_task="", status_code=200, **keywordarg)`
*   **Description:** Any argument passed as `key=value` is added directly to the JSON body.

#### 2. `RESPONSE_file`
Send a file for download or display.
*   **Signature:** `x.RESPONSE_file(path="", media_type="", download_name="", background_task="", disposition="attachment", status_code=200)`
*   **Description:** `disposition` is used to set the download (`attachment`) or display in browser (`inline`) mode.

#### 3. `RESPONSE_text`
Send a plain text response.
*   **Signature:** `x.RESPONSE_text(text="", background_task="", status_code=200)`

#### 4. `RESPONSE_streaming`
Send data in chunks (Streaming) for large files.
*   **Signature:** `x.RESPONSE_streaming(content="", media_type="", background_task="", status_code=200)`

#### 5. `RESPONSE_no_content`
Send a response with no body (usually for operations that don't need to return data).
*   **Signature:** `x.RESPONSE_no_content(background_task="")`

#### 6. `RESPONSE_redirect`
Redirect the user to another URL.
*   **Signature:** `x.RESPONSE_redirect(url="", background_task="", status_code=301)`

#### 7. `RESPONSE_html`
Send a raw HTML file from disk.
*   **Signature:** `x.RESPONSE_html(html_path="", background_task="", status_code=200)`

#### 8. `RESPONSE_html_jinja`
Send Jinja2 templates that require rendering.
*   **Signature:** `x.RESPONSE_html_jinja(html_path="", background_task="", status_code=200, **keywordarg)`
*   **Description:** `keywordarg` are variables that are replaced in the HTML template.

### ⚡ Background Tasks Capability

The `background_task` parameter is available in all the above methods, allowing you to execute operations **after sending the response to the client**.

#### Features and Technical Notes:
*   **Non-blocking:** Using `asyncio.create_task()` sends the response immediately and runs the task in the background.
*   **Error Handling:** Since tasks are separated from the request cycle, make sure to use a `try/except` block inside the task function to prevent errors from getting lost.
*   **Context Access:** Note that after sending the response, the `Request Context` is cleared. If the background function needs request information, extract it **before returning the response** and pass it as an argument to the function.

#### Practical Example:

```python
import asyncio
from nexelpy import RestApi, Route

async def log_action_task(action_name: str):
    try:
        await asyncio.sleep(2) 
        print(f"Log: {action_name} completed.")
    except Exception as e:
        print(f"Log Error: {e}")

@Route("/api/action", methods=["POST"])
async def perform_action():
    api = RestApi(__file__)
    
    # The response is sent immediately, while logging happens in the background
    return api.RESPONSE_json(
        status=True, 
        message="Action started", 
        background_task=log_action_task("User_Click_Action")
    )
```

## Static Files Addressing

In **NexelPy**, file address management is designed to intelligently support both **Absolute Pathing** and **Relative Pathing**. This feature allows you to call your files without worrying about changes in the directory structure.

### 1. Absolute Addressing
In this mode, addressing starts from the **Project Root**. This method is used when you want to specify the file path from the project's starting point.

**Structure:** `[Project_Root] / [Folder_Path] / [File_Name]`

**Examples:**
*   If the file is at `static/pic.png`:
    `example.com/static/pic.png`
*   If the file is at `views/home/script.js`:
    `example.com/views/home/script.js`

---

### 2. Relative Addressing
This is one of NexelPy's most powerful features. Using the `x.url()` method, you can calculate the file path **relative to the current file's location (Module Location)**. This ensures that if you move a folder, the internal addresses don't break.

#### Case 1: File in the same level or sub-folder of the module
*   **File Location:** `/views/home/home.py`
*   **Destination Location:** `/views/home/script.js`
*   **How to call:**
```python
x.url("./script.js")
```

#### Case 2: File in a sub-folder relative to the module
*   **File Location:** `/views/home/home.py`
*   **Destination Location:** `/views/home/scripts/script.js`
*   **How to call:**
```python
x.url("./scripts/script.js")
```

### Quick Comparison

| Addressing Type | Calculation Source | Main Use Case | Advantage |
| :--- | :--- | :--- | :--- |
| **Absolute** | Project Root | Public files like `static` or `assets` | High clarity in overall project structure |
| **Relative** | Current Module Location | Specific files of each view or module | Easy portability of modules |

## File Response Addressing

When using the `x.RESPONSE_file` method to send a file to the client, the system intelligently interprets the input path. You do not need to use `x.url()` to generate an address; instead, you can pass the path directly to the method.

### Path Interpretation Rules

The `RESPONSE_file` method decides whether to consider the address **relative** or **absolute** based on the presence or absence of a dot (`.`) at the beginning of the path:

#### 1. Relative Path
If the path starts with a dot (`.`), the address is calculated relative to the **current Python file's location**. This method is ideal for files located alongside the module or in its sub-folders.

*   **Example 1 (File alongside the module):**
    ```python
    # The file is in the same folder as this code
    return x.RESPONSE_file("./data.json")
    ```
*   **Example 2 (File in a sub-folder of the module):**
    ```python
    # The file is in the assets folder alongside the module
    return x.RESPONSE_file("./assets/report.pdf")
    ```

#### 2. Absolute Path
If the path starts with `/` (and has no dot), the address is calculated from the **Project Root**. This method is used to access public folders like `static` or `uploads` located in higher layers of the project.

*   **Example 1 (Static folder in root):**
    ```python
    # The file is at project_root/static/logo.png
    return x.RESPONSE_file("/static/logo.png")
    ```
*   **Example 2 (Direct access from root):**
    ```python
    # The file is at project_root/downloads/manual.pdf
    return x.RESPONSE_file("/downloads/manual.pdf")
    ```

### Quick Guide Summary

| Input Format | Address Type | Calculation Source |
| :--- | :--- | :--- |
| `./path/to/file` | **Relative** | Current Module Directory |
| `/path/to/file` | **Absolute** | Project Root |

## Client-Side Script Generation (Nexcript)

In traditional projects, JavaScript files are loaded statically in the browser. However, in NexelPy, serving scripts and managing file addresses is handled by the server. The **Nexcript** class is designed to solve two main challenges:

1. **Path Resolution:** Unlike static projects, on the server side, the browser does not know which folder the JS file is in to resolve relative paths (like `./logo.png`). Nexcript converts addresses to valid paths at compile time.
2. **Scoping:** When merging code, variable and function names may conflict. Nexcript automatically generates a unique token for each module to prevent conflicts.

### Basic Usage of Nexcript

To build a script, you use a `with` block. The current file (`__file__`) is mandatory for path detection. Your code goes inside the `add_script` method.

```python
from nexelpy import Nexcript

# The JS output file is automatically created alongside the Python file with a .js extension
with Nexcript(__file__) as n:
    n.add_script("""
        const el = scoping(); // Auto-scoped selector
        const img = url("./assets/logo.png"); // Converted to a valid path
        console.log("Nexcript is ready!");
    """)
```

### Addressing and Scoping Methods

Nexcript gives you two global functions in the JS environment:

*   **`url("./path")`**: Converts relative paths to absolute paths (from the project root).
*   **`scoping()` or `scoping(".selector")`**: Selects a DOM element using the unique token of that file. This means your code runs without conflicting with other parts of the page.

#### Scoping Example
```python
with Nexcript(__file__) as n:
    n.add_script("""
        // Finds the element based on this file's scope
        const btn = scoping("#my-btn"); 
        btn.addEventListener("click", () => alert("Clicked!"));
    """)
```

### TypeScript Support

If Node.js (version 22.6 or higher) is installed on your system, Nexcript will automatically detect TypeScript code and compile it to JavaScript. No additional configuration is needed.

```python
with Nexcript(__file__) as n:
    n.add_script("""
        interface User { name: string; }
        const user: User = { name: "Ali" };
        console.log(user.name);
    """)
```

### Export Path

By default, the JS file is saved alongside your Python file with a `.js` extension. If you want to save it in another folder (e.g., `static/js/`), use the `export_path` parameter:

```python
with Nexcript(__file__, export_path="../static/js/app.js") as n:
    n.add_script("console.log('Custom path');")
```

### Addressing the File in a View
To link the generated JS file to the HTML page, use the `x.url()` method:

```python
x = View(__file__)
x.script(parent=x.headTag, src=x.url("./script.js"))
```
If `export_path` is not specified, the generated JS file is created alongside the Python module with the same name.<br>
/views/home/homeview.py<br>
/views/home/homeview.js<br>

## Client-Side Style Generation (Nextyle)

**Nextyle** is a powerful tool for generating CSS code using Python syntax. This class replaces writing raw CSS files and allows you to build styles using programming logic (like loops and variables).

### Basic Usage of Nextyle

Like `Nexcript`, it starts with a `with` block, passing `__file__`. The generated CSS file is automatically saved alongside the Python file with a `.css` extension.

```python
from nexelpy import Nextyle

with Nextyle(__file__) as y:
    # Select the body tag and apply styles
    y.select("body").background_color("#f0f0f0").color("black")
    
    # Select a class and apply styles
    y.select(".card").padding("20px").border("1px solid #ccc")
```

### Selectors and Chaining

In Nextyle, you can chain method calls. For CSS properties written with `_` in Python (like `background_color`), Nextyle automatically converts them to CSS format (`background-color`).

#### Pseudo-classes and Pseudo-elements
To style specific states (like `hover` or `focus`), use the `hover()`, `focus()`, etc., methods:

```python
y.select(".btn").background_color("blue").color("white")\
    .hover().background_color("red")\
    .active().background_color("green")
```

#### Styling Children
Using the `nest` method on a previous selector, you can style its children:
```python
y.select(".card").padding("10px")
y.select(".card").nest("h2").font_size("24px")
```
Result:
```css
.card {
    padding: 10px;
}

.card h2 {
    font-size: 24px;
}
```

### Grid System and Breakpoints (Responsive)

Nextyle supports **Mobile-First**. You can set different values for different devices (like tablet and desktop) by passing `kwargs` to any property.

Default breakpoints in Nextyle (inspired by Bootstrap and Tailwind) are:
*   `sm` (large mobile)
*   `md` (tablet)
*   `lg` (desktop)
*   `xl` (large monitor)
*   `ul` (Ultra-Large)

```python
# Base style is 10px, on tablet it's 20px, and on desktop it's 30px
y.select(".container").padding("10px", md="20px", lg="30px")
```

### Using CSS Variables and Contexts

Nextyle uses `with` blocks to create complex CSS structures:

#### 1. Global Variables (`:root`)
```python
with y.vars(":root"):
    y.add_var(primary_color="#3498db", secondary_color="#e74c3c")
```

#### 2. Media Queries
```python
with y.media("(min-width: 1200px)"):
    y.select(".sidebar").display("none")
```

#### 3. Animations (Keyframes)
```python
with y.keyframes("fade-in"):
    y.step("0%").opacity("0")
    y.step("100%").opacity("1")
```
(Then to use the animation: `y.select(".box").animation_name("fade-in").animation_duration("2s")`)

#### 4. Font-face
```python
with y.font_face("MyFont"):
    y.src(y.url("./fonts/myfont.woff2"), format="woff2")
    y.font_weight("400")
```

### Importing External CSS and Raw Code

If you need to use external libraries (like Bootstrap) or raw code:

```python
# Import from a URL
y.import_css(y.url("./bootstrap.min.css"))

# Write raw CSS (relative URLs inside it are automatically corrected)
y.raw_css("""
    .custom-box {
        background: url("./bg.png");
    }
""")
```

### Export Path

By default, the CSS file is saved alongside the Python file with the same name and a `.css` extension:
*   `/views/home/homeview.py`
*   `/views/home/homeview.css`

If you want to save the output in another location (e.g., static folder), use the `export_path` parameter:

```python
with Nextyle(__file__, export_path="../static/css/style.css") as y:
    y.select("body").margin("0")
```

### Linking to HTML

To apply the generated styles to the page, simply link the generated CSS file to the page head using `x.url()`:

```python
x = View(__file__)
x.link(parent=x.headTag, rel="stylesheet", href=x.url("./homeview.css"))
```

### 🌐 Optimized Static Serving with Nginx (Optional)

By default, NexelPy handles static files (`/static/` and `.css`, `.js`, `.html` extensions) using its built-in server. While this is perfect for local development, for high-traffic production environments, it is highly recommended to let a Web Server like **Nginx** serve these files directly.

Nginx can serve static files much faster and with zero overhead for your Python application.

#### 1. Nginx Configuration Example

Add the following configuration to your Nginx site config (usually in `/etc/nginx/sites-available/your_site`). This tells Nginx to handle static files and pass everything else to Uvicorn (your Python app):

```nginx
server {
    listen 80;
    server_name yourdomain.com;  # Replace with your domain

    # 1. Serve static files (CSS, JS, HTML) directly
    # Requests for these files will never reach the Python app
    location ~* \.(css|js|html)$ {
        root /path/to/your/project;  # Replace with your NexelPy project root path
        expires 30d;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # 2. Serve static folder contents (images, fonts, etc.)
    location /static/ {
        alias /path/to/your/project/static/;  # Replace with your static folder path
        expires 30d;
        add_header Cache-Control "public";
        access_log off;
    }

    # 3. Pass all other requests to the Python application (Uvicorn)
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

*(Make sure to replace `root` and `alias` paths with your actual project paths).*

#### 2. Disable Static Mounting in NexelPy (Optional)

When Nginx is configured to serve your static files, you can tell NexelPy to stop serving them to avoid redundancy. You can do this by setting `mountStatics=False` during initialization:

```python
from nexelpy import Nexelpy

# Set mountStatics to False for optimal production performance
app = Nexelpy(__file__, mountStatics=False)
```

If Nginx is not configured but `mountStatics=False` is used, NexelPy's `StaticProductionVerifier` will log a helpful warning, letting you know that static files might be unreachable. This ensures you always know the status of your deployment without causing downtime.
